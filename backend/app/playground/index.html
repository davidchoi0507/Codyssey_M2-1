인디 앨범 스튜디오 — 백엔드 흐름 테스트

이 서버의 API를 그대로 호출하는 백엔드 흐름 확인용 페이지입니다. 실제 화면(디자인)은 프론트에서 만듭니다.
📋 테스트 방법 — 처음이면 꼭 읽어 주세요

이 페이지는 백엔드가 실제로 어떻게 동작하는지 확인하는 페이지예요. 버튼 배치·색·글꼴 같은 화면 디자인은 팀장님이 만드는 실제 화면에서 정해집니다. AI를 쓰는 버튼에는 횟수가 표시돼 있어요.

빠르게 둘러보기 (AI 사용 없음)

  • 1번 칸 아래 샘플곡 1~3: 결과물까지 만들어진 작업이에요. 커버·영상·채널 글·피칭 메일·ZIP을 바로 볼 수 있어요.
  • 노트 수정 테스트용 (수락 전): A&R 노트 단계에 멈춰 있는 작업이에요. 노트 수정·다시 듣기를 해 볼 수 있어요.
  • 샘플은 여러 사람이 같이 쓰는 작업이라, 누군가 고치면 다른 사람에게도 바뀐 채로 보여요. 마음껏 고치려면 직접 곡을 올려 주세요.

전체 흐름 (직접 곡 올리기)

  1. 곡 올리기 — mp3/wav(10분·200MB 이하), 곡 제목·아티스트 필수. 가사·곡 소개는 선택(넣으면 해석·피칭 메일에 반영). 동의 3개는 필수. 하루에 한 사람(같은 인터넷) 10곡까지예요(밴드 테스트 때는 3곡으로 줄여요).
  2. 진행 상태 — 업로드 → 수치 재는 중(BPM·키·에너지, 수 초) → 곡을 듣는 중(AI가 실제로 들음, 20~70초) → 해석 쓰는 중. 수치를 재면 BPM·파형이 먼저 보여요. 다른 곡이 처리 중이면 "차례를 기다리는 중 (n번째)"이 떠요.
  3. A&R 노트 확인 — AI가 곡을 듣고 쓴 해석이에요. 아래 방법으로 고칠 수 있어요.
    • 한 줄 수정: "이게 아니라 이거야"를 한 줄로 쓰면 AI가 해석·키워드·색·커버 방향을 그 방향으로 다시 써요(약 7초). 예: "터지는 게 아니라 체념이야"
    • 다시 듣기: AI가 곡을 처음부터 다시 듣고 해석을 새로 써요(20~70초). 가사를 나중에 추가했거나, 해석이 곡과 많이 다를 때 써요. 밴드가 한 줄 수정한 방향은 다시 들어도 유지돼요.
    • AI 다시 쓰기·다시 듣기 남은 횟수: 한 줄 수정 + 다시 듣기를 합쳐서 작업당 5회예요. 다시 듣기가 실패하면 횟수는 돌려줘요.
    • 직접 편집 (횟수 제한 없음): 아래 값을 고친 뒤 "직접 편집 저장"을 눌러야 저장돼요.
      • 무드 키워드: 쉼표로 구분, 1~5개
      • 색 3개: 색 칸을 눌러 색 고르기 (곡의 처음→절정→끝 느낌)
      • 커버 방향 3개: 커버를 그릴 때 쓰는 문장을 직접 고쳐 쓰기 (예: "비 오는 창가, 수채 일러스트")
      • 하이라이트 구간(숏폼 15초): 후보(★ = AI 추천)를 누르거나 슬라이더로 시작 지점을 옮기고 ▶ 이 구간 듣기로 확인
    • 해석 문장 자체는 직접 고칠 수 없고 한 줄 수정으로만 바뀌어요(해석과 근거 수치가 어긋나지 않게).
  4. 수락 — "이 해석으로 수락"을 누르면 커버 3장·채널 홍보 글 4개·피칭 메일(영·한)을 동시에 만들어요(약 40초). 수락하면 노트는 더 못 고쳐요.
  5. 결과물
    • 이 커버로 만들기: 고른 커버로 숏폼 15초·Spotify Canvas 8초·채널별 이미지·제목 얹은 커버를 만들어요(약 40초, AI 사용 없음). 다른 커버를 골라도 되고, 한 번 만든 커버로 다시 돌아가면 바로 보여요. 글(채널 글·피칭)은 어떤 커버를 골라도 같아요.
    • 다시 / 다시 쓰기: 커버·채널 글·피칭 메일을 하나씩 다시 만들어요. 요청 칸에 한 줄 쓰면 반영돼요(예: "사람 없이", "더 짧게"). AI를 쓰고, 항목마다 3회예요. 이전 버전도 남아요.
    • 직접 올린 사진: 밴드 사진을 올리면 커버 후보(cover-own)로 들어가요. 골라서 영상까지 만들 수 있어요.
    • ZIP 다운로드: 영상까지 만든 뒤 생겨요. 커버·영상·채널별 글과 이미지·피칭 메일·릴리즈 브리프가 들어 있어요.
    • 틱톡·인스타그램(릴스)에는 숏폼 영상이 같이 붙어요. 피칭 메일의 [대괄호]는 밴드가 직접 채우는 칸이에요.

맨 아래 "호출 기록"에 어떤 요청을 보냈고 얼마나 걸렸는지 남아요. 오류를 알려 주실 때 작업 ID(진행 상태 옆)와 같이 캡처해 주세요.

🙋 팀에 확인 요청 드리는 것 — 10/6까지 의견 주세요

모두

  • 여러 곡으로 다양하게 테스트하고 오류·이상한 점을 알려 주세요: 긴 곡/짧은 곡, 보컬 없는 곡, 영어 가사, wav/mp3, 큰 파일, 중간에 새로고침하거나 창을 닫았다 다시 열기(작업 ID로 열기), 버튼 연속으로 누르기 등.
  • A&R 노트: 해석이 곡과 맞는지, 방향성(말투·길이·근거 수치 정도)이 괜찮은지, 키워드·색·커버 방향이 곡에 어울리는지, 하이라이트 추천 구간이 정말 좋은 구간인지.
  • 커버 3종: 디자인 방향, 세 장이 서로 충분히 다른지, 곡 분위기와 맞는지, 이상한 그림(글자·손 모양 등)이 없는지.
  • 영상: 숏폼(훅 문구·확대 속도·파형·제목 위치·페이드)과 Canvas의 느낌, 샘플 영상으로 SNS에 올릴 만한지, 바꾸고 싶은 템플릿 요소.
  • 채널 홍보 글: 인스타·틱톡·스레드·X 각각의 말투·길이·해시태그가 실제 채널에 맞는지, 어색한 표현.
  • 피칭 메일: 영어·한국어 메일 품질, 큐레이터가 읽을 만한지, 빠진 정보(예: 발매일·링크·SNS).
  • 추가하고 싶은 기능·빼도 될 기능, 기다리는 시간이 너무 긴 곳.

팀장님 (화면)

  • 진행 화면 단계 이름(업로드 → 수치 재는 중 → 곡을 듣는 중 → 해석 쓰는 중)과 문구, 기다리는 동안 보여줄 것(먼저 나오는 BPM·파형 활용).
  • A&R 노트 화면 구성 — 한 줄 수정·직접 편집·하이라이트 슬라이더·다시 듣기 배치. 미리 듣기는 응답의 audio_url로 가능.
  • API 응답 구조(/docs)에서 바꾸거나 추가해야 할 필드.
  • 숏폼 템플릿 2·3번째 스펙(위치·색·글꼴·움직임), 채널 이미지 비율, 커버 위 제목 배치.

동의·개인정보 (팀원) — 누가 맡을지 팀장님이 정해 주세요

  • 지금 받는 정보: 음원 파일, 곡 제목·아티스트·장르·곡 소개·가사(선택), 접속 IP(하루 한도용), 동의 여부와 시각, 밴드가 쓴 수정 문장. 7일 뒤 자동 삭제(결과보고서용 처리 시간·수정 횟수 같은 지표만 개인정보 없이 남김).
  • 동의 문구 확정: 업로드할 때 체크하는 4개 항목의 실제 문장이 필요해요. 지금 1번 칸의 문장은 임시예요.
    1. 자작곡이며 권리를 가지고 있다는 확약 (필수)
    2. 개인정보 수집 — 무엇을, 왜, 얼마나(7일) 보관하는지 (필수)
    3. 음원이 Google Gemini로 전송되고, 무료 티어 특성상 Google의 AI 학습에 쓰일 수 있다는 안내 (필수)
    4. 발표 자료 사용 (선택) — 이 밴드의 곡·결과물(커버·영상·글)을 우리 팀의 최종 발표·결과보고서에 예시로 써도 되는지
  • 동의 문구 버전: 문구가 나중에 바뀔 수 있어서, 밴드가 어떤 문장에 동의했는지 동의 기록마다 버전 이름(예: v1-1008)을 함께 저장해요. 문장을 확정할 때 버전 이름도 하나 정해 주세요 (문장을 고치면 v2-…처럼 올리면 돼요).
  • 이메일·연락처를 받을지(결과 알림 등), 받는다면 보관 기간.
  • 테스트 밴드 안내문에 넣을 것: 처리 시간, 하루 3곡, 7일 보관, AI 생성 표기.
