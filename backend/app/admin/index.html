체험 기록

자동 사용 기록 + 마지막 설문 (발매 준비 작업 하나 또는 바로 공개한 곡 하나 = 체험 1건)

운영자 키를 넣고 불러오기를 눌러 주세요. '키 기억'을 켜면 이 브라우저에서는 다음부터 바로 열려요 (공용 PC에서는 끄세요).
이 페이지 읽는 법
  1. 먼저 날짜를 거르세요. 팀 QA·시연 작업이 섞이면 숫자가 왜곡돼요. 실제 테스트 시작일을 '이 날짜부터'에 넣으세요.
  2. '눈에 띄는 점'부터 읽으세요. 숫자에서 바로 읽히는 것을 문장으로 정리했어요. 빨간 표시는 먼저 볼 것이에요.
  3. '어디까지 갔나'에서 막대가 가장 크게 줄어드는 곳이 사람들이 멈춘 단계예요. 그 단계 화면을 의심하고, 체험 목록에서 그 단계에 멈춘 작업을 찾아 보세요.
  4. 사용 기록 = 실제로 한 일, 설문 = 느낀 점. 둘이 다르면(예: 만족한다고 했지만 ZIP을 안 받음) 사용 기록이 더 정확해요. 설문은 '왜'를 알려 줘요.
  5. 표본이 10건보다 적으면 비율은 한두 명에 크게 흔들려요. 퍼센트보다 건수와 자유 답변을 보세요.
  6. 자유 답변(고쳤으면 하는 점·오류)은 꼭 전부 읽으세요. 같은 말이 2번 이상 나오면 고칠 목록 1순위예요.
  7. 발표·보고서용은 CSV를 받아 엑셀 피벗으로 정리하세요(체험 1건 = 1줄). JSON에는 요약·눈에 띄는 점까지 들어 있어요.

눈에 띄는 점

    발매 준비 — 어디까지 갔나

    각 단계까지 간 작업 수 / 전체 발매 준비 작업

    어떻게 보나
    • 위에서 아래로 줄어드는 게 정상이에요. 바로 앞 단계보다 크게 줄어든 곳이 문제 후보예요.
    • 업로드→노트: 분석 실패·대기 시간 / 노트→수락: 해석이 안 맞음 / 결과물→ZIP: 받는 방법을 못 찾음·필요 없음.
    • ZIP을 안 받아도 '커뮤니티 공개'로 끝냈을 수 있어요 — 오른쪽 '쓴 기능'과 같이 보세요.

    쓴 기능

    한 번이라도 쓴 작업 수 / 전체 발매 준비 작업

    어떻게 보나
    • 많이 쓰인 기능 = 사람들이 원하는 것. 발표에서 '실제로 쓰인 기능'으로 보여 주기 좋아요.
    • 거의 안 쓰인 기능은 못 찾았는지, 필요 없는지 자유 답변으로 확인하세요.
    • '복사·열기'는 화면이 보내는 기록이라, 화면에 그 버튼이 없으면 0이에요.

    마지막 설문

    어떻게 보나
    • 1~5점 문항은 평균과 4~5점 비율을 같이 보세요. 평균 4 이상이면 좋음, 3 미만이면 원인을 찾아야 해요.
    • '자료' 표는 행(커버·영상·글·메일)마다 '많이 고쳐야/쓰기 어려워요'가 많은 줄이 개선 1순위예요. '안 봤어요'가 많으면 화면에서 못 찾은 거예요.
    • 안내(보관·AI 전송) 문항이 낮으면 동의 문구·안내 위치를 손봐야 해요.
    • 설문은 끝까지 간 사람만 보기 쉬워서 실제보다 좋게 나올 수 있어요.

    체험 목록

    어떻게 보나
    • 최근 순이에요. '어디까지'로 멈춘 단계, '실패'로 오류가 난 작업을 찾고, '응답'을 펼치면 그 사람의 설문 답이 보여요.
    • ID(job:…)로 서버 로그·작업 기록을 찾아볼 수 있어요. '삭제됨'은 보관 기간이 지나 파일은 지워지고 숫자만 남은 작업이에요.
