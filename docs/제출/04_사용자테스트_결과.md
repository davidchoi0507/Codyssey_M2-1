# 발매로 — 사용자 테스트 결과와 개선

> 작성: 백엔드(원일) 초안 · 2026-10-19 · 수치는 서버 자동 기록(`scripts/usage_report`)과 마지막 1분 설문에서 뽑음
> 참여 인원은 명단 대신 **서버 기록의 서로 다른 사용자 수**로 셌어요 (아래 1-1). 팀원 사용도 포함한 숫자예요.

## 1. 테스트 방식

| 차수 | 날짜 | 대상 | 방식 |
| --- | --- | --- | --- |
| 1차 | 10/6~8 | 팀 | 실제 곡으로 전체 흐름, 의견 정리 |
| 2차 | 10/16 | 팀 (이은희·신미영) + 개선안 리포트 | 피드백 33개 → 담당별로 나눠 반영 |
| 3차 (실사용자) | **10/16~19** (본 테스트 10/18) | 팀 + 외부 사용자, 서버 기록 기준 서로 다른 사용자 35명 (1-1) | 배포된 서비스를 직접 사용 → 서버가 단계·기능 사용을 자동 기록 → 마지막 1분 설문 7문항 |

- 자동 기록: 어디까지 갔는지(업로드 → 노트 → 수락 → 커버 → 완성 → ZIP), 쓴 기능, 걸린 시간, 실패·재시도
- 설문: 만족도, 재사용 의향, AI 해석 정확도, 결과물 활용 가능성(커버·숏폼·홍보 글·피칭 메일), 안내 이해도, 고칠 점, 오류

### 1-1. 참여 인원 (서버 기록, 10/16~19)

서버는 사람을 로그인 계정 또는 브라우저 익명 ID로 구분해요(10/16부터). 같은 작업·곡에 계정과 브라우저 ID가 함께 찍히면 한 사람으로 합쳤고, IP로는 합치지 않았어요(같은 와이파이의 여러 사람이 한 명이 되므로). 이름·닉네임은 보지 않고 숫자만 셌어요.

| 한 일 | 서로 다른 사용자 |
| --- | --- |
| 서비스를 쓴 사람 (아래 중 하나라도) | **35** |
| 내 곡으로 발매 준비 | 19 |
| 들어봐에 곡 공개 | 8 |
| 들어봐에 반응(별점·태그·한마디) | 16 |

| 날짜 | 쓴 사람 | 내 곡 작업 | 들어봐 반응 | 설문 |
| --- | --- | --- | --- | --- |

- 팀원 사용도 포함한 숫자예요. 한 사람이 휴대폰·PC처럼 다른 기기로 들어오면 따로 셀 수 있어 **많게 잡힌 쪽**이에요.
- 10/15 이전 작업(14건)에는 사람 구분값이 없어 위 숫자에서 빠졌어요 (1·2차 테스트).
