## 0. 한눈에 보기

- **팀이 정한 새 방향(로드맵):** "단순 비주얼 생성"에서 **"유통사 반려 위험을 줄이는 원스톱 음원 발매 패키징"**으로.
  - 한 번 입력 → **규격 검사 → 유통사별 제출 자료 Export** → (나중에) 발매 후 반응 확인.
- **조사 결론(팀원 4개 자료가 대체로 일치):**
  1. 개인은 멜론·Spotify·YouTube Music에 **직접 못 올리고 반드시 유통사를 거친다** (공식 출처 확인됨).
  2. **규격은 플랫폼이 아니라 유통사마다 다르다** → 서비스는 "유통사별 규격 프로파일"을 가져야 한다.
  3. 경쟁 서비스 **뮤즈플랫폼**이 이미 "발매 + 방송심의 대행 + AI 커버" 묶음을 제공 → "원스톱"만으로는 약하고 **"올리기 전에 미리 검사 + 제출 서류 자동 작성 + 권리(커버곡·AI) 체크"**가 차별점.
- **지금 백엔드와의 관계:** 이미 만든 것(제출 전 검수 24항목, 발매 캘린더, 에디토리얼 피칭, 커버 검사, 3000px 커버, Canvas, ZIP)이 로드맵의 **절반 이상**을 이미 덮고 있음. 새로 필요한 핵심은 **구조화 입력(크레딧·가사·피처링), 권리 자가진단, 유통사별 Export**.
- **⚠ 정리가 필요한 충돌 3가지** (§5): ① 로드맵(제출 패키징)과 10/9 회의 결정(누구나·반응 공간 커뮤니티)의 비중 ② 로드맵 일정은 4주인데 남은 시간은 10일 ③ 자료마다 다른 수치(요금·반려율 등).

## 0.5 사용자 커뮤니티에서 들은 고민 — 팀 조사와 합쳐 계획서에서 논의할 방향

**추가 조사:** 방구석 음악가, "음악 한번 만들어 볼까?" 하는 사람들이 모이는 커뮤니티에서 가장 많이 들린 목소리 두 가지.
1. **"방법을 모르겠다."** 음악은 만들었는데 멜론·Spotify에 어떻게 올리는지 모른다.
2. **"반응이 궁금하다."** 내 노래를 다른 사람들이 어떻게 생각하는지 알고 싶다.

**이 두 가지를 푸는 쪽으로 정리해 보면:**
| 고민 | 팀 조사·로드맵에서 가져올 것 | 이미 있는 것 |
|---|---|---|
| ① 어떻게 발매하지? | 발매 구조 안내(유통사 경유), 유통사 고르기, 규격 검사, 구조화 입력, 권리 자가진단, 유통사별 제출 자료, 일정 | 제출 전 검수 24항목, 발매 캘린더, 커버·Canvas·카피·피칭, ZIP |
| ② 다들 어떻게 생각할까? | 발매 후 3사 통계(2순위, 수동 입력) | 커뮤니티 '들어봐'(발매 전·후 누구나 들어보고 반응) |

- 대상: 전문 인디 뮤지션보다 **처음 발매해 보는 사람**. 그래서 "규격 검사 도구"에 그치지 않고 **처음부터 끝까지 따라가는 안내**가 필요함.
- 로드맵의 제출 패키징은 ①의 핵심 엔진으로 쓰고, ②는 커뮤니티로 채운다.
- **일정: 다음 주(10/12~10/18) 1주일이 최대.** 그 안에 되는 범위로 자른다 → 03에서.

## 2. 방향 전환 로드맵 (pivot_roadmap.pdf)

### 2.1 왜 바꾸나
| | 기존 | 새 방향 |
|---|---|---|
| 정체성 | 이미지·영상 AI 생성 | 원스톱 음원 유통·발매 패키징 |
| 문제 | 한 번 써보고 끝(재방문 이유 없음) | 실제 Spotify·멜론 발매 규격에 맞게 패키징 |

기존 기술은 버리지 않고 옮겨 씀:
| 기존 자산 | → 새 역할 |
|---|---|
| AI 커버 아트 | 3000px 규격을 검사한 앨범아트 |
| 주파수 비주얼라이저 | Spotify Canvas · 릴스 티저 |
| librosa 오디오 분석 | 음원 규격 검사 (WAV / Peak) |
| A&R 카피라이팅 | 플랫폼용 앨범 소개글 · 보도자료 |

### 2.2 5단계 발매 흐름 (Zero-Rejection Submission Pipeline)
1. **메타데이터 빌더** — 곡명·피처링 표기 규칙 자동 교정, 크레딧 서식
2. **오디오 프리플라이트** — WAV 16/24bit, 44.1/48kHz, True Peak −1dB, 무음 구간 검사
3. **커버 & 소개글** — 3000px 검사, AI 커버, 장르·무드 기반 보도자료
4. **홍보 비주얼 팩** — Spotify Canvas 9:16 루프, 릴스·쇼츠
5. **유통사 제출 Export** — 포크라노스/DistroKid 양식 엑셀 자동 기입 + ZIP

## 3. 팀원 조사 핵심 정리

### 3.1 발매 구조 (모든 자료 공통, 공식 확인됨)
```
창작자 ──▶ 유통사 ──▶ 멜론·지니·FLO·벅스·VIBE (국내)
                 └──▶ Spotify·YouTube Music·Apple Music … (해외)
```
- Spotify: 레이블·유통사가 전달한 음원만 받음. 메타데이터는 Spotify Metadata Style Guide를 따름.
- YouTube Music: 유통사가 전달한 음원+커버+메타데이터로 **Art Track 자동 생성**, "아티스트명 - Topic" 채널에 배치.
- 멜론: 멜론과 계약한 유통사를 통해서만 서비스, **정보 수정도 유통사를 통해서만**.
- **DistroKid 공식 스토어 목록에 멜론 없음** → 국내 발매는 국내 유통사가 따로 필요 ("해외용 + 국내용 병행"이 흔한 해법).

### 3.2 유통사 비교 (개인 창작자 관점, Eun Hee 보고서 기준)
| 유통사 | 개인 가입 | 국내 | 해외 | 비용 | 기간 | 특징 |
|---|---|---|---|---|---|---|
| 포크라노스 | 심사 | O | O | ~15% (2차) | 확인 불가 | 통과 어려움 |
| 미러볼뮤직 | 심사 | O | O | ~20% (2차) | 심사 1~2주 (2차) | 곡 완성도 중심 |
| **뮤즈플랫폼** | **누구나** | O | O | 무료+20% / 7만 원+15% (공식) | **2주 이내** (공식) | 방송심의 대행·AI 커버아트 — **직접 경쟁** |
| 루트노트 | 누구나 | O (AI 음원 불가) | O | 무료 15% / 프리미엄 0% | 2~3주 (2차) | **WAV 안 받음(FLAC/MP3)** |
| DistroKid | 누구나 | **후기상 불가** | O | $24.99/년~ (2차) | 1~3일 (2차) | 구독 끊으면 음원 내려감 |
| 포노(FONO) | — | O | — | 수익 배분 | 2~4주 | Claude·Copilot 자료의 국내 대표 — **팀 조사 자료 기준, 공식 미확인** |

> 한국 창작자 현실적 조합: ① 국내외 한 번에 = 뮤즈플랫폼/루트노트 ② 해외 DistroKid + 국내 유통사 ③ 인디 레이블(미러볼·포크라노스) 지원 + 대안 준비.

### 3.3 등록 규칙 (서비스가 검사할 것)
| 영역 | 규칙 | 근거 |
|---|---|---|
| 음원 | 무손실(WAV/FLAC), 16bit/44.1kHz 일반적, 1GB 이하 | DistroKid 공식 |
| 음원 | True Peak −1dB는 **권고** (반려 여부는 유통사별, 확인 불가) | Spotify 공식 |
| 커버 | 1:1, **3000×3000 권장(최소 1000)**, JPG, RGB(sRGB) | DistroKid 공식 |
| 커버 | Spotify 자체 기준은 640~10,000px — **3000px는 유통사 관행** | Spotify 공식 |
| 커버 | URL·QR·가격·스트리밍/SNS 로고·실물 매체 표기·흐림·업스케일·사용권 없는 사진 금지 | DistroKid·Spotify 공식 |
| 제목 | 피처링·Explicit·연도를 제목에 쓰지 않고 **별도 항목**으로 | Spotify Style Guide |
| 아티스트 | 모든 발매에서 철자 동일, 별칭·번역 한 칸에 같이 쓰지 않기 | Spotify Style Guide |
| 크레딧 | 작곡가 **실명** 필수, 작사·작곡·편곡 역할 구분 | DistroKid 공식, 포노 |
| 가사 | **복사 가능한 텍스트** (이미지 X) | 포노 |
| 권리 | 커버곡 라이선스(DistroKid 최대 14영업일), 커버 이미지 사용권, 다른 가수 목소리 흉내 금지 | DistroKid·Spotify 공식 |
| AI 음원 | DistroKid: AI 생성 트랙은 AI 크레딧 필요 / 루트노트: 국내 플랫폼 AI 음원 불가 | DistroKid 공식 / 유통사 |
| 일정 | Spotify 에디토리얼 피칭 **발매 7일 전까지** (1곡씩) | Spotify 공식 |
| 일정 | 유통사 제출 D-21~D-28 권장 (포노 2~4주, DistroKid 약 4주 전 권장) | 공식+팀 조사 |

### 3.4 발매 후 반응 (2순위 기능 후보)
| | Spotify for Artists | YouTube Analytics for Artists | 멜론 파트너센터 |
|---|---|---|---|
| 이용 조건 | 프로필 접근 승인(수일) | Official Artist Channel 필요 | 본인 이름 발매 앨범 + 가입 승인 |
| 대표 지표 | 스트리밍·청취자·저장·플레이리스트 | 조회수·시청시간·순 시청자 | 감상자수·좋아요·공유 |
| 자동 연동 | — | — | — |

- 설계 원칙: 서로 다른 지표를 **합치지 않고 나란히**, 기준 시각 표기, 발매일 기준(D+7, D+30) 비교.

## 5. 정리가 필요한 충돌 (03 기획서에서 결정)

### 5.1 로드맵 vs 10/9 회의 결정(DECISIONS #30·#31)
| | 10/9 회의 (백엔드 기록) | pivot_roadmap (팀 자료) |
|---|---|---|
| 대상 | 누구나 (개인·학생·관심 있는 사람) | 인디 뮤지션 (유통사 제출하는 사람) |
| 중심 | ① 안전한 첫 발매 ② 쉬운 홍보 ③ **반응 받는 공간** | **유통사 제출 패키징** (반응은 2순위 대시보드) |
| 이미 만든 것 | 커뮤니티 '들어봐' 배포 | 로드맵엔 커뮤니티 없음 |

→ ①(안전한 첫 발매)은 로드맵과 정확히 같은 방향. ③ "반응 공간"을 **우리 커뮤니티(발매 전 반응)**로 볼지, **3사 통계 대시보드(발매 후 반응)**로 볼지 팀에 확인 필요. 둘은 다른 기능.
→ §0.5 조사로 보면 둘 다 필요하지만 사용자가 가장 궁금해하는 건 "다른 사람들 반응"이라 **커뮤니티를 먼저**, 3사 통계는 2순위로 두는 안을 계획서에서 논의.

### 5.2 일정
- 로드맵은 4주(W1~W4)지만 **10/20 제출까지 10일**. 남은 일정을 보면 개발은 **다음 주(10/12~10/18) 1주일이 최대**.
- 로드맵 W1(조사) 산출물인 **유통사 엑셀 양식을 아직 못 받음** → Export 기능은 양식이 와야 정확히 만들 수 있음.

### 5.3 대상 유통사
- 로드맵: 포크라노스 / DistroKid · Claude·Copilot: DistroKid / 포노(FONO) · Eun Hee: **뮤즈플랫폼이 개인에게 가장 현실적이자 경쟁자**, 포크라노스는 심사형이라 통과 어려움.
- → 1단계 Export 대상 2곳을 확정해야 함.

### 5.4 역할
- 로드맵의 "팀원 3: 유통사별 엑셀 생성(openpyxl), ZIP"은 지금까지 **백엔드 전담**(DECISIONS #17)이던 영역과 겹침 → 03 §5에서 정리: 화면은 팀장, 서버 코드는 백엔드, 팀원 2·3은 프론트·백엔드에 필요한 자료·문서 조사, 팀원 4는 팀장 보조·테스트.
