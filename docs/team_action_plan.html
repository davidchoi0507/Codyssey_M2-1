💡 아키텍처 진단 결론

현재 백엔드의 비동기 작업 큐, FFmpeg 인코딩, REST API 통신 구조는 이미 프로덕션 레벨로 완벽하게 구축되어 있습니다.
따라서 파이썬 시스템 코드를 뜯어고칠 필요가 전혀 없으며, 결과물의 '시각적 퀄리티(화풍 디렉팅)'와 '프론트엔드 연출(목업)'만 보강하면 최상의 시연이 가능합니다.

🚨 학생들이 반응이 없었던 진짜 원인

  • 전형적인 '싸구려 AI 짤' 느낌: 매끄럽고 반질반질한 디지털 CG 질감, 과도한 형광색 채도 ➔ 음악인들의 예술적 자존심에 스크래치
  • 단순 평면 이미지의 한계: 폰트도 없고 입체감도 없는 사각 그림만 덩그러니 보여주니 '앨범 자켓'이 아니라 '웹 검색 짤'로 인식
  • 소구점 불일치: 곡 완성에 쫓기는 학생들에게 '거창한 발매 홍보'는 비현실적 ➔ "인스타 스토리에 신곡 스포할 15초 감성 영상"이 필요함

🚫 '자체 디퓨전 탑재/학습'이 불가한 이유

  • GPU 인프라 비용 폭탄: Stable Diffusion/Flux 구동 시 VRAM 16GB+ 필수 (월 수십만 원 고정 비용 발생)
  • 현재 서버는 CPU 환경: Oracle 무료 티어는 CPU 2코어로 디퓨전 모델 추론 불가
  • 학습 시간 절대 부족: 데이터셋 수집, 라벨링, LoRA 학습에 최소 2주 소요 (남은 시간 4일)
  • 제안서 기조 일치: 원일 님 제안서에서도 오픈소스 모델 운영은 유료화 이후로 보류함
